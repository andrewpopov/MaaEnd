# 队伍管理

更新日期：2026-10-20。

**队伍管理**分组连接已保存的配队攻略、账号证据、养成规划与材料刷取。先运行**推荐队伍**，在**规划角色养成**中选择阵容，核对消耗后再使用**刷取队伍养成材料**。养成准备与战斗截图任务也归入此分组。

## 推荐队伍

推荐功能将 42 个已保存阵容与账号角色列表对比，优先显示角色齐全的队伍，然后按近期检查的 Mobalytics 变体及角色、武器等级完成度排序。这是攻略适配建议，不是伤害模拟排名，也不表示所有攻略条件均已满足。具体战斗场景、武器潜能、属性形态、终结技充能效率与循环要求仍应以来源为准。

可以从历史审查提供标准化角色列表，否则使用当前账号扫描导出作为不完整的推荐证据。可用包含 `account_uid`、`as_of`、`roster` 的新版 `data/TeamManagement/roster.json` 替换。缺失和过期信息仍会显示。装备截图只表示当前装备的方案，不能证明其他方案或已拥有装备不存在。

## 使用已有装备方案

1. 打开角色，进入 **Gear**，点击右上角 **Gear Plan**。
2. 选择已命名的方案行，在预览中核对四件装备、属性和套装效果。选中方案不会装备它。
3. 检查装备上的角色头像。方案可能引用其他角色正在穿戴的装备；移动共用装备前应检查整队。
4. 点击 **Apply** 并检查共用装备确认。重新打开 **Gear**，核对四件装备及套装效果。
5. 检查最终形态和充能要求。Arcane 在 `INT >= WILL` 时为 INT 形态，在 `WILL > INT` 时为 WILL 形态。方案名称本身不能证明形态正确。

2026-10-20 检查时账号共有 15 个已保存方案。`HotWorksArcane` 对应 Arcane 当前的 INT 配装，属性为 707 INT、335 WILL。用户表示另有 WILL 方案，但此次检查尚未验证。建议制作新装备前，应先检查并复用已有方案。

## 保存或更新装备方案

1. 装备预期的四件装备，核对型号、属性与套装效果。
2. 打开 **Gear Plan** 并选中 **Current Gear**，在 **Save As** 中输入区分角色用途的名称，再点击 **Save**。
3. 重新打开保存的方案行，将四件装备和效果与当前配装对比。如能取得物理装备 ID，应记录这些 ID 及与其他角色的共用关系。
4. 替换已有方案时，明确选择其覆盖控件并先核对目标名称。应用方案与保存方案是不同操作，不应为了穿戴装备而覆盖或删除方案。

## 规划队员养成

选择准确阵容及角色等级、武器等级、普通技能等级（1–9）与独立专精等级（0–3）目标。专精 0 表示保留当前投资，不会降低技能。任务在 `data/TeamManagement/requests/` 下创建独立请求，并生成 JSON、HTML 报告。已有请求会保留；修改目标时需要重新核对消耗序列。角色配装记录保留攻略中的武器、四槽装备备选与技能投资顺序。

养成队列支持角色等级、武器等级、单个普通技能、独立专精步骤、晋升、装备制作与精锻消耗。专精要求普通技能达到 9 级。每个已核算步骤需要角色、养成类型、前后状态、准确材料消耗、账号 UID、观察时间和证据文件，并单独采集当前等级。消耗序列必须从当前状态覆盖到目标，不能重叠、缺段或超出目标。未知消耗不会视为免费。

在可见游戏界面运行**采集养成或装备方案预览**，可在管理采集目录保存新截图和 OCR。核对数量、物品身份与账号 UID 前，采集内容仍是未审查状态。

目前实现负责规划这些养成，独立队员升级任务提供精英 4、80–90 级的限额升级路线。规划器本身**不会**点击晋升、武器、技能、制作、精锻或装备方案控件。启用自动培养操作前，这些剩余执行路线仍需界面识别和结果验证。手动养成后，应重新采集等级与消耗再使用剩余队列。

## 升级选定队员

打开选定队员的 **Overview**，在**升级队员（80–90）**中输入准确名称、80–90 级目标及折金预算。预算为 0 时仅预览下一级并保存观察到的消耗。正数预算允许在预算和目标内逐级升级。本任务不启用低等级、晋升或武器升级路线。

路线核对账号 UID 与队伍成员身份，识别两种认知载体图标，读取选择数量与货币，并在每次提交前重新核对预览。提交后验证新等级以及载体、折金的准确变化。提交前先保存收据；结果不确定时保留待确认收据，阻止自动重试。Perlica 82 → 83 的试验已手动验证，消耗 36,000 经验与 13,043 折金。自动 OCR 与识别路线仍需部署后进行完整预览验证。

## 刷取缺失材料

刷取任务使用选定队伍的已验证消耗和材料保留量，汇总全队消耗，显示已知库存与缺口，并将每种库存目标设置为 `总养成消耗 + 保留量`。任务强制重新扫描培养素材，再交由现有补给计划 Pipeline 选择关卡并追踪奖励。它不会修改完整日常的协议空间目标。

支持现有补给计划的 16 类资源，包括角色、武器经验，晋升、技能素材，以及 Warp Plasma-Coated Slide 等高级材料。报告单独列出不支持的物品，不猜测刷取来源。未知库存仍在报告中显示未知，由实时库存扫描检查。过期或账号不匹配的消耗证据会阻止刷取。

在本任务中选择刷取编队与战斗设置。理智药默认选择**结束任务**；主动开启用药后使用现有到期时间选项。现有协议空间成功、失败次数控件仍可使用。领取奖励后会检查资源目标，达到目标即停止该资源刷取。刷取结束不会自动消耗材料进行养成。

## 实现与验证

`tools/team_manager.py` 提供推荐、规划与刷取命令。`TeamManagementAction` 调用它并应用经过校验的刷取覆盖；游戏导航由 Pipeline 管理。报告与请求存放在 `data/TeamManagement/`。十个定向规划测试覆盖消耗与保留量、未知库存、过期或错误账号消耗、遗漏与重叠养成、共用装备、Arcane 形态、不支持的材料与角色匹配。

管理任务及刷取衔接需要重新构建 Go Service 并刷新资源。此功能的离线测试没有验证实时刷取或养成执行。在检查实时路线前，应保持日常预设中的任务关闭。
